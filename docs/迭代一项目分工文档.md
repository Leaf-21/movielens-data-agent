# 迭代一项目分工文档

## 一、项目名称

**Agent 驱动的 Hadoop 数据清洗与五维质量评估系统**

## 二、项目目标

本项目以 MovieLens 1M 数据集为基础，构建一个由 Agent 驱动的数据清洗与质量评估系统。

用户通过前端输入自然语言需求后，Agent 自动组织任务并调用 Hadoop，完成：

1. 原始数据检查；
2. 清洗前五维数据质量评分；
3. 数据清洗；
4. 清洗后五维数据质量评分；
5. 清洗前后结果对比；
6. 清洗问题及处理原因解释；
7. 评估报告生成。

最终系统需要输出清洗后的数据、数据版本、清洗规则版本、任务标识、`T1/T2` 时间边界以及五维质量评估报告。

# 四、成员A：Hadoop 数据处理与五维质量评估

### 1. 主要职责

负责项目底层的数据处理工作，使用 Hadoop 完成 MovieLens 数据的**检查、清洗以及五维质量评分**。

文档明确要求 Hadoop 实际承担数据处理和评分计算，清洗与评分不能仅停留在 Agent 层面模拟。

### 2. 具体任务

#### （1）MovieLens 数据分析

负责分析：

- `ratings.dat`
- `movies.dat`
- `users.dat`

重点检查：

- 编码问题；
- 字段数量异常；
- `::` 分隔符问题；
- 缺失值；
- 数据类型异常；
- 重复数据；
- 数据关联问题；
- ID 异常；
- 时间戳异常；
- 跨表数据不一致。

文档列出的具体检查方向包括评分范围、重复评分、MovieID/UserID 关联、用户属性格式等。

#### （2）设计数据清洗规则

确定哪些问题需要：

- **修复**
- **去重**
- **隔离**
- **删除**

特别需要区分真正的数据错误和正常业务现象，不能为了提高评分而随意修改数据。

#### （3）使用 Hadoop 实现清洗

根据确定的规则编写 Hadoop 程序，例如：

```
原始 MovieLens 数据
        ↓
Hadoop 数据读取
        ↓
数据格式检查
        ↓
异常数据识别
        ↓
数据清洗
        ↓
正常数据
   +    异常/隔离数据
```

#### （4）设计五维评分方案

负责设计：

- Accurate：准确性
- Complete：完整性
- Unique：唯一性
- Up-to-date：时效性
- Consistent：一致性

文档要求学生自行确定具体指标、计算方法、分值范围和权重。

例如可以制定：

| 维度       | 主要评价内容                       |
| ---------- | ---------------------------------- |
| Accurate   | 字段值是否合法、评分是否在合理范围 |
| Complete   | 必要字段缺失比例                   |
| Unique     | 重复记录比例                       |
| Up-to-date | 时间戳是否处于规定时间范围         |
| Consistent | 字段格式及跨表关联是否一致         |

具体指标和计算公式由成员A负责提出，并与另外两名成员讨论确认。

#### （5）清洗前后评分

必须使用**同一套评价标准**计算：

```
原始数据
   ↓
五维评分 Before
   ↓
Hadoop 清洗
   ↓
清洗后数据
   ↓
五维评分 After
   ↓
Before / After 对比
```

文档明确要求清洗前后使用同一评价口径，使结果具有可比性。

### 3. 成员A最终提交

- Hadoop 数据清洗代码
- Hadoop 五维评分代码
- 数据质量检查结果
- 清洗规则说明
- 清洗前评分结果
- 清洗后评分结果
- 清洗后的 MovieLens 数据
- 异常/隔离数据
- 数据量变化统计

# 五、成员B：Agent 后端与系统流程

### 1. 主要职责

负责整个系统的**Agent 核心逻辑和 Hadoop 调度**。

Agent 不直接承担实际的数据计算，而是负责理解用户需求、组织任务、调用 Hadoop 工具，并解释最终结果。文档规定 Hadoop 负责实际的数据处理和评分，Agent 负责任务组织、结果解释和前端展示。

### 2. 具体任务

#### （1）Agent 用户需求解析

例如用户输入：

> 请使用默认规则清洗 MovieLens 1M，评估清洗前后的五个数据质量维度。

Agent 需要识别：

```
数据集：MovieLens 1M
任务：数据清洗
评分：五维质量评估
规则：默认规则
```

#### （2）设计 Agent 工作流程

整体流程：

```
用户输入自然语言
        ↓
      Agent
        ↓
解析任务需求
        ↓
调用 Hadoop
        ↓
清洗前质量评分
        ↓
执行数据清洗
        ↓
清洗后质量评分
        ↓
获取结果
        ↓
Agent 整理结果
        ↓
生成评估报告
        ↓
返回前端
```

系统需要实现一次提示完成整个任务，而不是要求用户手动执行 Hadoop 命令或中间步骤。

#### （3）封装 Hadoop Tool

把成员A编写的 Hadoop 程序封装成 Agent 可以调用的工具。

例如：

```
hadoop_quality_check()
hadoop_clean_data()
hadoop_quality_score()
hadoop_get_result()
```

Agent 可以按照任务需要依次调用这些工具。

#### （4）任务状态管理

需要区分：

```
PENDING
   ↓
RUNNING
   ↓
SUCCESS
```

异常情况：

```
RUNNING
   ↓
FAILED
```

执行失败时需要明确告诉用户：

- 哪个环节失败；
- 为什么失败；
- 是否产生了部分结果。

不能在任务失败时生成虚假的评分结果。

#### （5）结果解释

Agent 负责把 Hadoop 返回的数据转化为用户容易理解的结果。

例如：

```
清洗前：
Complete = 92.5

清洗后：
Complete = 98.7

变化：
+6.2
```

并进一步解释：

> 完整性提高主要由于清洗过程中对关键字段缺失记录进行了隔离。

同时需要区分：

- 修复；
- 去重；
- 隔离；
- 删除。

不能简单地把“删除异常数据”描述为“问题已经修复”。

#### （6）版本及时间边界管理

负责记录：

- 数据版本；
- 清洗规则版本；
- 任务 ID；
- `T1`；
- `T2`。

其中：

```
T1 = 训练期截止时间
T2 = 验证期截止时间
测试数据 > T2
```

后续迭代需要保证数据版本和时间范围一致。

### 3. 成员B最终提交

- Agent 核心代码
- Agent Prompt/流程设计
- Hadoop Tool 接口
- 任务调度模块
- 状态管理模块
- 结果解析模块
- 评估报告生成模块
- 数据版本/规则版本管理
- Agent API

# 六、成员C：前端与系统测试

### 1. 主要职责

负责系统前端页面以及整个项目的功能测试、联调和最终演示。

文档要求提供简易前端，让用户能够输入自然语言请求、查看执行状态、查看五维评分及清洗结果，并继续向 Agent 提问。

### 2. 具体任务

#### （1）设计前端页面

页面至少包含以下模块：

```
┌──────────────────────────────┐
│       MovieLens 数据治理      │
├──────────────────────────────┤
│ 自然语言任务输入              │
│                              │
│ [请输入清洗与评估需求……]       │
│                              │
│          [开始执行]            │
├──────────────────────────────┤
│ 任务状态：运行中/完成/失败      │
├──────────────────────────────┤
│       五维质量评分对比          │
│                              │
│         清洗前   清洗后   变化  │
│ Accurate                       │
│ Complete                       │
│ Unique                         │
│ Up-to-date                     │
│ Consistent                     │
├──────────────────────────────┤
│ 数据清洗结果                   │
│ 数据量变化 / 修复 / 去重 / 隔离 │
├──────────────────────────────┤
│ Agent 结果解释                 │
├──────────────────────────────┤
│ 继续提问：[              ]      │
└──────────────────────────────┘
```

#### （2）评分结果展示

前端需要展示：

| 指标       | 清洗前 | 清洗后 | 变化 |
| ---------- | ------ | ------ | ---- |
| Accurate   | XX     | XX     | XX   |
| Complete   | XX     | XX     | XX   |
| Unique     | XX     | XX     | XX   |
| Up-to-date | XX     | XX     | XX   |
| Consistent | XX     | XX     | XX   |

具体数值由 Hadoop 实际运行结果提供，前端不得自行生成。

#### （3）展示数据处理结果

展示：

- 原始数据量；
- 清洗后数据量；
- 修复数量；
- 去重数量；
- 隔离数量；
- 典型异常记录；
- 处理原因。

#### （4）Agent 对话功能

实现用户继续追问，例如：

> 为什么 Complete 提高了？

> 删除了多少条数据？

> 哪些数据被隔离了？

> 为什么某些问题没有解决？

Agent 根据实际执行结果进行回答。

#### （5）系统测试

成员C负责最终测试，包括：

**功能测试**

- 能否提交任务；
- Agent 能否正常调用 Hadoop；
- Hadoop 是否成功返回结果；
- 前端是否正确显示结果。

**异常测试**

- Hadoop 执行失败；
- 数据文件不存在；
- 数据格式异常；
- Agent 调用失败；
- 任务超时。

**结果一致性测试**

重点检查：

```
Hadoop实际结果
      ↓
Agent返回结果
      ↓
前端展示结果
```

三个环节的数据是否一致。

### 3. 成员C最终提交

## 十、三人分工总结

**成员A：负责“数据能不能正确处理”**

> MovieLens 数据分析 → Hadoop 清洗 → 五维质量评分 → 输出真实数据结果。

**成员B：负责“Agent 能不能自动完成任务”**

> 用户需求理解 → 调用 Hadoop → 任务管理 → 结果分析 → 报告生成。

**成员C：负责“用户能不能看懂并使用系统”**

> 前端页面 → 结果展示 → Agent 追问 → 系统测试 → 最终 Demo。

这种分工能够把项目拆成 **数据层、Agent/后端层、展示/测试层**，三个人职责比较清晰，同时又能在最终阶段进行完整联调。
