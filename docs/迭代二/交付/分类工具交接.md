# 分类工具交接（成员A → 成员B/C，迭代二）

> 对应交付清单：两个分类算法的输入、输出、模型版本、评价指标与限制；
> 供 B 注册工具、C 展示结果、迭代三复用。
> 版本：`data_version=movielens-1m-v2-clean-v1`、`cleaning_rule_version=rule-v2`、
> `feature_version=feat-v1`、`split_version=split-v1`。

## 一、调用方式（给成员B）

两种工具都是**进程内 Python 调用**，不走迭代一的 HTTP 服务：

```python
import sys, os
sys.path.insert(0, os.path.join(REPO_DIR, 'agent', 'tools'))
from classification import predict

result = predict.classify(user_id=1, movie_id=1193, algorithm=None)   # None = 两种都跑
```

- `algorithm`：`None` / `"both"` → 两种算法对照；`"gnb"` / `"cart"` → 只跑指定算法。
- `prediction_time`：历史事件回测时传入目标事件时间戳（epoch 秒）；交互式请求不传，
  结果中 `prediction_time_basis` 会标明按训练期快照（`T1`）预测。
- 失败抛 `classification.schemas.ToolError`，`to_dict()` 得到接口扩展规范 §六 的错误对象；
  `to_legacy_error(stage)` 可映射回迭代一的 8 个错误码（细分码放在 `detail.sub_code`）。

命令行等价入口（联调用）：

```bash
python3 agent/tools/classification/predict.py --user-id 1 --movie-id 1193
python3 agent/tools/classification/predict.py --user-id 1 --movie-id 1193 --algorithm cart
```

字段说明：

| `prediction_time_basis` | 特征截止时点的口径 | 是（区分回测/实时） |

## 三、错误码

| 细分码 | 触发条件 | 映射到迭代一错误码 |
|---|---|---|
| `UNKNOWN_USER` | UserID 在 `users.dat` 与 `ratings.dat` 中都不存在 | `INVALID_REQUEST` |
| `UNKNOWN_MOVIE` | MovieID 不存在 | `INVALID_REQUEST` |
| `MODEL_NOT_FOUND` | `artifacts/` 下没有对应模型 | `DATA_NOT_FOUND` |
| `VERSION_MISMATCH` | 模型的特征版本 ≠ 当前 `feat-v1` | `INVALID_DATA_VERSION` |
| `DATA_UNAVAILABLE` | 清洗快照缺失或不可读 | `DATA_NOT_FOUND` |
| `INVALID_PARAMETER` | 未知 `algorithm` 或超参数越界 | `INVALID_REQUEST` |
| `ALGORITHM_ERROR` | 模型无法输出概率/决策分数 | `AGENT_EXECUTION_ERROR` |
| `INTERNAL_ERROR` | 其它未预期异常 | `INTERNAL_ERROR` |

## 四、实测指标（真实运行，非占位）

| 算法 | 验证 ROC-AUC | 验证 PR-AUC | 测试 ROC-AUC | 测试 PR-AUC | 测试 F1 | 测试 Acc | 阈值 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 朴素贝叶斯（gnb） | 0.6838 | 0.7059 | 0.6838 | 0.6942 | 0.7136 | 0.6560 | 0.420510 |
| 决策树（cart） | 0.7768 | 0.7967 | 0.7710 | 0.7872 | 0.7527 | 0.7084 | 0.496270 |

对照基线：测试期多数类比例 0.5542（全判正类的准确率）；作业四的确定性规则基线准确率 0.5420。
结论：两种算法都优于两条基线，决策树在全部指标上领先（测试 ROC-AUC +0.087，F1 +0.039）。

## 六、已知限制（必须在界面上可见）

1. 概率未校准：朴素贝叶斯的后验被推到 0/1 两端，决策树输出的是叶结点频率；两者都只能当作分数排序使用。
2. 冷启动占比高：验证期约 76.6%、测试期约 47.9% 的评分来自训练窗口内未出现的用户。这类样本的用户历史特征走全局均分回退，`features_used` 中会标记 `fallback_global_mean`。
3. 属性缺失：2,994 条评分涉及 15 个无属性 UserID，职业/年龄分别走 `unknown` 与 `-1`。
4. 标签噪声：4,328 个主键冲突在清洗阶段整组隔离，剩余样本的标签仍可能受注入值影响。
5. 时间范围：模型只使用 `t <= T1` 的数据训练，不反映 2000-11-22 之后的偏好变化。

## 七、给成员C的展示建议

- **真实样例**：`docs/迭代二/交付/分类结果样例.json`，含两份实际运行输出——用户 4169/电影 260（有历史）与用户 1/电影 1193（历史不足回退），可直接照着渲染两种展示路径；文件头记录了生成命令与数据/特征版本。
- 分类结果卡片：目标 `(UserID, MovieID)` + 两种算法并列的类别与概率 + 阈值 + `model_version` + 指标（ROC-AUC / PR-AUC）。
- 概率旁必须标注"未校准"，并给出阈值（例如"分数 0.87 ≥ 阈值 0.50 → 高分"）。
- 若 `features_used` 中出现 `fallback_global_mean`，显示"该用户/电影历史不足，预测可信度较低"。
- 决策树结果的 `explain` 可渲染成决策路径；朴素贝叶斯没有对应字段，显示"不提供路径解释"。
- 失败时直接展示 `error.code` 与 `error.message`，不要显示任何默认预测。

## 八、Agent 接入（registry 契约）

成员B的 `agent/tools/registry.py` 要求每个工具暴露 `run(payload, acfg, rcfg)` 并支持
`python3 -I <file> --request req.json --output out.json`。分类侧适配层已就位：

- 模块：`agent/tools/classification/classification_tool.py`
- 入口：`run`
- 工具名：`classification_gnb` / `classification_cart`

**payload（runner 构造）**：

```json
{
  "algorithm": "gnb",
  "user_id": 1,
  "movie_id": 1193,
  "prediction_time": null,
  "data_version": "movielens-1m-v2-clean-v1",
  "feature_version": "feat-v1"
}
```

`algorithm` 必填（一个工具只跑一种算法；两种算法对照由 runner 调用两次完成，与聚类同构）。
`prediction_time` 省略时按训练期快照预测，信封中 `prediction_time_basis` 会标明口径。
`data_version` / `feature_version` 传入则会校验，不一致返回 `VERSION_MISMATCH`。

**系统接入状态（2026-10-21 补齐）**：三处断点已在 main 修复并回归：

| 断点 | 修复 |
|---|---|
| `analysis.json` 分类段为空（且原结构多套了一层 `algorithms`，`registry._node` 读不到）-> `registry.require` 抛 `MODEL_NOT_FOUND`，router 报“类别 classification 尚无登记算法” | 条目改为与 `clustering` 同构、直接挂在 `classification` 下：`gnb` / `cart` 均指向 `classification.classification_tool`（`parameters: {}`，`timeout_s: 300`） |

cart `cls-0c388dfb5da5`），信封含 runner 必需的全部键。回归测试：
`tests/agent/test_classification_integration.py`（登记、模块文件、payload、聚类 payload 不变）。

清洗快照不在仓库内（`*.dat` 被 `.gitignore` 排除），本地联调前按 `data/DATASETS.md`
