# 迭代二接口扩展规范

## 一、目的与兼容原则

本文件为迭代一已有接口增加分类、聚类和降维能力。它是对现有 `docs/迭代一/分工/接口规范文档.md` 的**扩展**，不要求重写或覆盖迭代一接口。若现有代码中已经存在等价任务创建、状态查询和结果查询接口，优先复用并在本文件登记最终路径；任何字段变更必须通过 Issue 与 PR 协商。

接口采用 HTTP + JSON + UTF-8。以下路径及字段是团队新增的建议约定，必须在开发初期由三人确认并冻结。

## 二、公共约定

### 2.1 通用任务状态

| 字段值 | 含义 |
|---|---|
| `PENDING` | 已创建，等待执行 |
| `RUNNING` | 正在执行 |
| `SUCCESS` | 已完成且结果可用 |
| `FAILED` | 执行失败 |

数据不可用等原因通过 `error.code` 表达，例如 `DATA_UNAVAILABLE`、`UNKNOWN_USER`、`UNKNOWN_MOVIE`、`INSUFFICIENT_HISTORY`、`MODEL_NOT_FOUND`、`INVALID_PARAMETER`、`VERSION_MISMATCH`、`ALGORITHM_ERROR`、`INTERNAL_ERROR`。失败不得返回伪造的成功结果。

### 2.2 公共任务创建响应

各创建接口成功接收请求后均返回任务标识：

```json
{
  "task_id": "实际生成的唯一任务ID",
  "task_type": "classification",
  "status": "PENDING",
  "message": "任务已创建"
}
```

以上是结构示意，实际 `task_id` 由系统生成。不得把示意字符串作为真实结果。

### 2.3 公共状态/结果查询

优先复用迭代一的通用接口；如当前仓库未实现，可新增：

- `GET /api/tasks/{task_id}`：查询状态、当前阶段和错误信息；
- `GET /api/tasks/{task_id}/result`：查询已生成的结果。若任务未完成，不返回虚构的最终结果。

推荐状态响应字段：`task_id`、`task_type`、`status`、`stage`、`message`、`error`（失败时）。

### 2.4 版本字段

与分析结果有关的响应应尽可能提供：
- `data_version`：迭代一清洗数据版本；
- `cleaning_rule_version`：迭代一清洗规则版本（若可用）；
- `feature_version`：分类特征版本；
- `profile_version`：用户画像版本；
- `model_version`：模型版本；
- `result_version`：聚类/降维输出版本；
- `T1`、`T2`：实际采用的时间边界或其登记标识；
- `algorithm`、`parameters`、`metrics`；
- `code_version`：对应 Git commit 或代码版本。

## 三、分类任务

### 3.1 创建分类任务

`POST /api/analysis/classification/tasks`

请求字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `query` | string | 是 | 用户自然语言问题 |
| `user_id` | string/number | 是 | 目标 UserID，按数据 schema 约定类型 |
| `movie_id` | string/number | 是 | 目标 MovieID，按数据 schema 约定类型 |
| `algorithm` | string/null | 否 | 指定一个已实现算法；未指定/null 时运行两种算法对照 |
| `data_version` | string | 是 | 迭代一清洗数据版本 |
| `feature_version` | string/null | 否 | 特征版本；不传时使用已登记默认版本 |
| `prediction_time` | string/null | 否 | 历史事件回测时可指定目标事件时间；交互式预测不传时，按模型登记的训练期可用信息预测，并在结果中说明预测时点口径 |
| `parameters` | object/null | 否 | 用户指定的允许参数；须校验范围 |

示意请求：

```json
{
  "query": "预测用户对这部电影是否会给出4分及以上评分",
  "user_id": "USER_ID",
  "movie_id": "MOVIE_ID",
  "algorithm": null,
  "data_version": "实际清洗数据版本",
  "feature_version": null,
  "prediction_time": null,
  "parameters": null
}
```

不得要求调用者传入目标事件 `Rating`。目标评分不能进入目标事件的预测特征。若是对历史目标事件进行回测，应由系统使用目标事件时间或对应评估记录确定特征截止点；若交互式请求未提供 `prediction_time`，须使用模型登记的训练期可用信息，并在结果中标明预测时点口径，不能静默使用目标事件之后的行为。

### 3.2 分类结果结构

`GET /api/tasks/{task_id}/result` 的结果应至少包含：

```json
{
  "task_id": "实际任务ID",
  "task_type": "classification",
  "status": "SUCCESS",
  "data_version": "实际数据版本",
  "feature_version": "实际特征版本",
  "target": {"user_id": "USER_ID", "movie_id": "MOVIE_ID"},
  "results": [
    {
      "algorithm": "实际算法名称",
      "model_version": "实际模型版本",
      "predicted_class": "HIGH_RATING",
      "positive_probability": null,
      "decision_score": null,
      "parameters": {},
      "metrics": {},
      "limitations": []
    }
  ],
  "split_version": "实际切分方案版本",
  "T1": "项目已登记的T1",
  "T2": "项目已登记的T2"
}
```

`positive_probability` 只有在所选算法实际支持且经过定义时才填写；否则置 `null` 并说明。`predicted_class` 可采用 `HIGH_RATING` / `LOW_RATING`，具体枚举在编码前冻结。若未指定算法，`results` 应有两项实际算法结果。

## 四、聚类任务

### 4.1 创建聚类任务

`POST /api/analysis/clustering/tasks`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `query` | string | 是 | 自然语言问题 |
| `user_id` | string/number | 与 user_ids 二选一 | 查询单个用户的群体归属 |
| `user_ids` | array | 与 user_id 二选一 | 待分析用户集合；可按团队约定支持批量 |
| `algorithm` | string/null | 否 | 指定算法；未指定时运行两种聚类算法对照 |
| `data_version` | string | 是 | 清洗数据版本 |
| `profile_version` | string/null | 否 | 画像版本；不传时使用已登记默认版本 |
| `parameters` | object/null | 否 | 聚类算法参数 |

至少提供 `user_id` 或 `user_ids` 之一。未知用户、画像缺失或历史不足必须返回明确错误/状态。

### 4.2 聚类结果结构

结果至少包含：
- `task_id`、`task_type`、`status`；
- `data_version`、`profile_version`、`result_version`；
- `results[]`：每个实际运行算法的名称、参数、版本和指标；
- `assignments[]`：`user_id`、`cluster_id`（或团队约定的噪声标识）、`is_noise`（算法不支持时可为 null）；
- `cluster_summaries[]`：群体标识、人数、由实际统计生成的偏好摘要、代表性内容和解释依据；
- `limitations[]` 与异常信息。

若未指定算法，必须包含两种算法的真实结果，且应能区分两种结果的 `algorithm` 和 `result_version`。

## 五、降维任务

### 5.1 创建降维任务

`POST /api/analysis/dimensionality-reduction/tasks`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `query` | string | 是 | 自然语言问题 |
| `user_ids` | array/null | 否 | 待展示用户集合；不传时使用已登记分析集 |
| `algorithm` | string/null | 否 | 指定降维算法；未指定时运行两种算法对照 |
| `target_dimensions` | integer/null | 否 | 目标维数；需按所选算法校验 |
| `information_retention_threshold` | number/null | 否 | 信息保留阈值；仅在算法支持时使用 |
| `clustering_algorithm` | string | 是 | 用于降维前后比较的聚类算法 |
| `clustering_parameters` | object/null | 否 | 聚类对照参数 |
| `data_version` | string | 是 | 清洗数据版本 |
| `profile_version` | string | 是 | 输入用户画像版本 |
| `parameters` | object/null | 否 | 降维算法参数 |

### 5.2 降维结果结构

每种算法的结果至少包含：
- `algorithm`、`model_version`、`result_version`、`parameters`；
- `data_version`、`profile_version`；
- `original_dimensions`、`reduced_dimensions`；
- `information_retention`：指标名、指标值、定义；算法不支持或未测量时为 `null` 并说明；
- `resource_usage`：`elapsed_ms`，以及能够真实测量的内存/资源指标；未测量需明确标注；
- `coordinates[]`：用户 ID 与坐标，例如 `x`、`y`。二维可视化至少需要有效的两维坐标；
- `clustering_comparison`：同一用户集合上的降维前/降维后聚类算法、参数、指标及差异；
- `limitations[]`。

不能把不同算法不等价的信息保留指标直接当成同一度量横向比较；报告要说明指标定义。

## 六、统一错误响应

```json
{
  "task_id": "实际任务ID或null",
  "status": "FAILED",
  "error": {
    "code": "DATA_UNAVAILABLE",
    "message": "无法获取指定的数据版本",
    "details": {}
  }
}
```

建议错误码：`INVALID_REQUEST`、`DATA_UNAVAILABLE`、`VERSION_MISMATCH`、`UNKNOWN_USER`、`UNKNOWN_MOVIE`、`INSUFFICIENT_HISTORY`、`MODEL_NOT_FOUND`、`INVALID_PARAMETER`、`ALGORITHM_ERROR`、`INTERNAL_ERROR`。根据实际情况选择，不需要把所有错误都伪装成 HTTP 200 成功。

## 七、Agent 工具命名约定

具体算法名称须先核对课程 PPT。确定后，按任务类型提供独立工具，例如：
- `classification_<algorithm_slug>`（两种）；
- `clustering_<algorithm_slug>`（两种）；
- `dimensionality_reduction_<algorithm_slug>`（两种）。

所有工具应使用统一输入校验、错误结构和元数据字段。Agent 路由规则：用户指定算法 → 仅调用对应工具；未指定算法 → 调用该类别的两种算法并提供对照；输入信息不足 → 先返回明确提示或可操作的缺失字段错误，不制造结果。

## 八、联调顺序

1. 全员确认本接口文档并合并 PR。
2. A/B/C 各自按固定 schema 写工具及单元测试。
3. B 使用假请求但真实 schema 做工具注册/路由测试；若使用 Mock 结果，必须只用于开发测试并标记。
4. A/B/C 提供本地真实运行结果，完成工具联调。
5. C 将真实 API 接入前端，验证各字段和错误状态。
6. 接口字段如变更，先改文档，再改调用方，通过 PR 记录兼容措施。
