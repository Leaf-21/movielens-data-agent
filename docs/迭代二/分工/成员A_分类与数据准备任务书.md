# 成员A任务书：数据准备、特征工程与分类

## 一、职责目标

负责迭代一清洗数据在迭代二中的正确接入、统一数据切分和可复用特征准备，并实现分类任务的两种算法工具。预测目标为：给定用户与电影组合，预测该用户在目标评分事件中是否会给出 **Rating >= 4**。

## 二、工作范围

### 1. 数据与版本检查

- 使用迭代一输出的清洗数据，不绕过清洗流程直接使用未经治理的压缩包训练。
- 记录清洗数据版本、清洗规则版本、输入路径/快照标识、可获得的校验值、`T1/T2` 和本次代码 Git commit。
- 检查 `ratings`、`users`、`movies` 的关联键、字段类型和空值处理。
- 统计训练、验证和测试记录数及标签分布；实际数值必须由当前清洗快照运行获得，不直接抄用原始数据集统计作为本轮结果。

### 2. 时间切分和特征工程

统一切分：
- 训练集：`Timestamp <= T1`；
- 验证集：`T1 < Timestamp <= T2`；
- 测试集：`Timestamp > T2`。

分类约束：
- 标签：`label = 1` 当且仅当目标记录的 `Rating >= 4`；否则 `label = 0`。
- 目标事件的 `Rating` 只用于标签和评估，不能作为预测特征。
- 目标事件发生后的评分、统计或用户行为不得用于该事件的预测特征。历史事件回测必须使用目标事件时间作为特征截止点；交互式请求未提供目标时间时，应按已登记的训练期快照口径预测并在结果中说明，不能静默纳入未来行为。
- 若采用历史评分统计作为特征，必须以目标事件发生时间为截止点，并排除目标事件本身及未来事件。
- 用户/电影 ID 作为关联键使用，不应无依据地按连续数值含义解释。
- 类别编码、标准化、特征筛选等需学习参数的预处理步骤，只能在训练期拟合，再应用于验证/测试期。

### 3. 分类算法

从课程 PPT 中选择两种分类算法，先在本文件末尾登记算法名称和 PPT 页码。对每种算法分别实现、训练、保存和评估，不把两种算法混成一个不可区分的黑盒。

每种算法至少应：
- 有明确的训练函数和预测函数；
- 支持输入 `user_id`、`movie_id`、数据/特征版本等必要信息；预测请求不要求调用者提供目标评分；
- 输出预测类别 `HIGH_RATING` / `LOW_RATING`，以及算法支持的正类概率或决策分数；不支持的量应返回 `null` 并注明原因；
- 保存模型标识、算法名、参数、训练数据范围、特征版本和代码版本；
- 在验证集上做模型/阈值选择；方案冻结后在测试集上做最终评价；
- 报告适用限制，例如未知用户、未知电影、历史行为不足、概率不可用等。

### 4. 工具封装

建议位置：`agent/tools/classification/`。该目录是供 Agent 调用的算法工具实现区，不改变成员A在迭代一中负责的数据层协作职责。

建议拆分：
```text
agent/tools/classification/
├── common_features.py
├── algorithm_one.py
├── algorithm_two.py
├── train.py
├── predict.py
└── schemas.py
```

文件名中的 `algorithm_one/two` 在课程 PPT 算法确认后替换为实际名称。与 B 约定统一调用入口和结果结构；禁止私自更改公共字段。

### 5. 测试

- 标签生成边界测试：评分为 3、4、5 的标签应符合定义。
- 特征泄漏测试：目标 Rating 不出现在输入特征中；目标时间之后的记录不参与该事件历史特征。
- 时间切分测试：三个时间段互不重叠，边界判断正确。
- 未知 UserID/MovieID 和模型文件缺失时，返回明确状态，而不是默认预测。
- 检查模型能够加载，重复执行时版本和配置可追踪。
