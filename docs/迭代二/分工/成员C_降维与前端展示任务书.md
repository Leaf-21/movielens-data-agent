# 成员C任务书：降维、可视化、前端与系统验收

## 一、职责目标

负责降维任务的两种算法工具、降维前后聚类结果对照、二维可视化，以及前端对分类、聚类和降维结果的统一展示。成员C同时牵头系统测试和验收记录，但 A/B 仍需负责修复各自模块的问题。

## 二、工作范围

### 1. 降维算法

从课程 PPT 中选择两种降维算法，并分别封装为 Agent 可独立调用的工具。具体算法名称需要先核对课程 PPT 并登记出处。

每种算法应支持或明确说明：
- 输入用户集合或用户画像版本；
- 原始画像维度与特征版本；
- 算法名称、参数和模型/结果版本；
- 实际输出的降维维度和坐标；
- 可计算时的信息保留情况；如果算法没有可直接解释的统一信息保留指标，应说明所用指标和局限，不得伪造“解释方差”等指标；
- 运行耗时及可获取的资源开销；无法可靠获取的资源指标应明确标注未测量；
- 降维前与降维表示上的聚类结果及其指标比较；
- 二维可视化使用的坐标字段和颜色/图例含义。

### 2. 降维前后聚类对照

- 使用同一批目标用户或明确说明样本差异，避免直接比较不可比的结果。
- 原始画像上的聚类和降维表示上的聚类应记录所用聚类算法及参数。
- 对照报告至少包括：样本范围、原始维数、降维维数、算法参数、信息保留指标及解释、聚类评价指标、执行时间和可获得的资源开销。
- 不应仅凭二维图视觉分离程度宣称某种方法必然更优；结论应由实际指标和图表共同支撑。

### 3. 前端展示

沿用现有 `frontend/src/` 和 `frontend/public/`，至少支持：
- 自然语言问题输入与任务提交；
- 任务状态、当前阶段和失败原因；
- 分类结果：用户/电影、预测类别或正类概率/决策分数、模型版本、指标和限制；
- 聚类结果：用户群体归属、群体摘要、代表性内容、历史不足提示；
- 降维结果：二维图、原始/目标维度、信息保留情况、压缩前后聚类指标和资源开销；
- 两种算法对照、数据切分方式、版本信息；
- 结果依据、未验证内容、局限及继续追问入口；
- 画像、预测和群体结果样例，以及评价报告和必要图表的查看/获取。

前端字段必须来自 Agent 接口。不得在页面里硬编码示例数据作为成功结果；开发阶段若使用 Mock 数据，必须显著标记为 Mock，生产/演示模式应显示实际任务返回值。

### 4. 测试与验收组织

- 编写前端状态、结果展示和错误状态测试。
- 维护端到端用例：自然语言输入 → Agent 路由 → 算法工具 → 结果返回 → 前端展示。
- 验证未知 ID、历史不足、任务执行失败、数据版本不一致和结果尚未生成等情况下的提示。
- 检查三类结果页面使用同一数据版本、特征/画像版本和任务 ID。
- 汇总测试报告和未解决问题，不得把未运行测试写成通过。

## 三、建议代码与产物位置

```text
agent/tools/dimensionality_reduction/  # 两种降维工具
frontend/src/                          # 页面与图表组件
frontend/public/                       # 静态资源
tests/frontend/                       # 前端测试
 reports/test-report/                  # 测试报告
 reports/quality-report/               # 分析/评价报告索引或导出件
```

实际目录可以遵循已有框架的规范；若需要新增子目录，通过 PR 说明即可。
