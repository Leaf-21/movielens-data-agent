## 一、使用方式

每项由负责人执行并填写结果、证据路径和 Git commit。未执行的测试不能勾选为通过；如果因环境或数据不可用无法执行，应标记“未完成/阻塞”并写原因。

测试状态建议统一为：`PASS`、`FAIL`、`BLOCKED`、`NOT_RUN`。

## 七、端到端场景

至少执行以下真实流程：

1. 分类：提交指定 UserID 和 MovieID 的自然语言预测请求，完成任务并展示预测类别、可用概率/决策分数、模型版本和限制。
2. 分类对照：不指定算法，确认两种分类算法均被调用，结果可比较。
3. 聚类：查询一个用户或一组用户，展示群体归属、摘要和代表性内容；再测试历史不足用户。
4. 聚类对照：未指定算法时比较两种聚类方法，并展示参数和适用指标。
5. 降维：提交用户集合，获得两种算法的坐标、信息保留情况、资源开销和二维图。
6. 降维前后比较：确认聚类前后使用一致的用户样本或明确说明差异，比较相应指标。
7. 异常：输入未知 ID、错误参数、无效数据版本，确认返回明确状态与错误原因。
8. 追问：围绕已有结果提问，确认 Agent 回答来自真实结果；超出证据时明确说明不能确认。
