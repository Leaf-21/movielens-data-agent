# 迭代二数据与实验规范

## 一、数据输入和版本

1. 输入必须是迭代一产出的 MovieLens 1M 清洗快照。不得绕过数据治理流程直接把原始压缩包作为本轮正式建模输入。
2. 每次实验至少记录：数据版本、清洗规则版本、实际数据路径/快照标识、可取得的校验值、`T1`、`T2`、代码 Git commit、特征/画像版本、算法名和参数。
3. 迭代一没有给出可在本文件中确认的具体日期值时，不得自行猜测 `T1/T2`；运行时读取项目登记值并将实际值写入报告。
4. 如输入数据版本、`T1/T2` 或特征版本不一致，任务应停止或明确标记版本不匹配，不得把多次实验的产物拼在一起。

## 二、时间切分规范

沿用需求文件定义的时间边界：

| 子集 | 时间条件 | 使用方式 |
|---|---|---|
| 训练集 | `Timestamp <= T1` | 拟合模型、预处理器、用户历史画像和降维模型（按各算法方案记录） |
| 验证集 | `T1 < Timestamp <= T2` | 算法选择、参数调整、阈值选择及开发阶段对比 |
| 测试集 | `Timestamp > T2` | 方案确定后进行最终评价，不用于反复调参 |

必须先固定数据切分逻辑，再进行算法对比。报告中记录各子集真实记录数、时间范围和类别分布；这些数据需要运行后计算。

## 三、分类任务防泄漏约束

1. 预测目标是目标评分事件的二分类标签：`Rating >= 4` 为高分正类，否则为非高分类。
2. 目标事件的 `Rating` 是生成标签和计算评价指标的依据，不是预测输入特征。
3. 目标事件发生后的任何评分事件或聚合统计不能进入该目标事件的预测特征。
4. 历史偏好特征应以目标事件的时间戳为截止点，只使用当时已发生的信息，并排除目标事件本身。
5. 用户/电影元数据是否可用于目标预测，需要在实验方案中说明可获得时点和局限；不能仅因某列存在就默认它在预测时一定可用。
6. 会学习参数的特征处理步骤（例如编码器、缩放器、特征选择器）在训练期拟合后，再用于验证/测试数据；不得对全量数据先拟合再切分。
7. 测试集结果只在实验方案和参数冻结后生成。若测试结果用于修改模型，则修改后的模型应使用新的实验版本并重新说明评价边界。

## 四、用户画像与聚类规范

1. 画像构建只使用训练期历史偏好；每个画像特征须有名称、含义、聚合方式、时间范围、缺失处理和版本。
2. 聚类训练时保存画像输入版本、用户集合、算法及参数、随机种子（算法适用时）、拟合时间和输出版本。
3. 验证阶段用于算法/参数选择；测试阶段只在方案冻结后用于最终评价。
4. 群体摘要必须由真实群体统计生成。解释中应区分“观测到的群体偏好”和“对用户动机的推测”；没有证据时不得描述用户心理或动机。
5. 对无历史或历史不足的用户，应明确标注，不得用群体平均值伪装成该用户可靠画像，除非这种补值方案已明确记录并说明限制。
6. 评价指标要记录定义和适用条件。不同聚类算法产生的标签编号通常只表示类别标识，不能直接按编号大小解释群体含义。

## 五、降维与公平对照规范

1. 记录输入画像版本、样本用户集合、原始维数、降维目标维数、实际参数、拟合数据范围、模型/结果版本和坐标版本。
2. 不能把测试期信息用于拟合降维模型后再宣称是独立测试。若部署方案是仅在训练画像上拟合，再应用到新用户，应记录所选算法是否支持该应用方式。
3. 降维前与降维后聚类对照尽量使用相同用户集合；若集合不同，报告必须说明原因，不能直接进行不公平比较。
4. 信息保留指标随算法而异。只报告所选算法能够定义、实际计算的指标；不适用或未测量时，标记为“不适用/未测量”，不要填入推测值。
5. 记录实际运行耗时；峰值内存等资源项只有真实测量时才报告。各算法应尽可能使用同一运行环境、样本范围和资源限制。
6. 二维图必须提供轴含义、点代表的对象、颜色/图例含义和样本范围。不能仅凭图像外观直接得出算法优劣结论。

## 六、每次实验记录模板

每个正式实验至少登记以下字段，可保存在报告 Markdown/JSON 中：

```json
{
  "experiment_id": "运行时生成",
  "task_type": "classification | clustering | dimensionality_reduction",
  "data_version": "实际数据版本",
  "cleaning_rule_version": "实际清洗规则版本",
  "T1": "项目实际登记值",
  "T2": "项目实际登记值",
  "split_version": "实际切分版本",
  "feature_or_profile_version": "实际版本",
  "algorithm": "实际算法名称",
  "algorithm_source": "课程PPT章节和页码",
  "parameters": {},
  "code_commit": "实际Git commit",
  "metrics": {},
  "artifact_paths": [],
  "limitations": []
}
```

这是字段模板，不是实验结果；实际运行前不得把占位内容用于演示真实结果。

## 七、必须保留的迭代三产物

- 分类：模型、特征定义/版本、阈值（若有）、算法配置、评价指标、适用限制。
- 用户画像：训练范围、画像字段、画像版本及用户画像数据或可重建流程。
- 聚类：模型/结果版本、每个用户的群体归属、群体摘要、参数、指标和噪声标记（算法适用时）。
- 降维：模型、坐标、原始/降维维度、参数、信息保留说明、运行资源记录及聚类对照结果。
- 通用：输入数据版本、清洗规则版本、`T1/T2`、代码 commit、创建时间、输出路径和校验信息（可用时）。

模型和坐标的存储位置需由团队结合现有仓库大小和交付要求确定。不要提交 `ml-1m.zip`；大体量或不适合直接入 Git 的产物，应按项目统一方式归档并在报告中记录可获取位置、版本和校验值。
